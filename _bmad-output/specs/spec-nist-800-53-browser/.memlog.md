- (note) Inputs: prd.md (finalized, fully absorbed -> sources) and ARCHITECTURE-SPINE.md (finalized, adopted -> companions, not duplicated).
- (decision) Why: pain to solve (800-53 Rev5 PDF unwieldy, NIST's own search clunky) + vision to realize (fast, deep-linkable, phone-readable OSCAL reader), for a broad/mixed audience.
- (capability) CAP-1 Browse by family: intent -- user can browse the full Rev5 catalog by Control Family, drilling family->control->detail. success -- every published family/control reachable via the tree, none dropped.
- (capability) CAP-2 Baseline filter: intent -- user can filter list views to one Baseline (Low/Moderate/High/Privacy). success -- each control/enhancement shows baseline membership; filtered view is itself deep-linkable.
- (capability) CAP-3 Control detail with inline enhancements: intent -- user can read a control's statement and expand/collapse its enhancements in place. success -- expanding doesn't navigate away; each enhancement individually deep-linkable.
- (capability) CAP-4 ISO 27001 crosswalk: intent -- every control detail page shows related ISO/IEC 27001:2022 clause(s) from NIST's crosswalk. success -- verified against transcribed crosswalk data; explicit 'no mapping published' state when none exists, never blank.
- (capability) CAP-5 Search: intent -- user can search by control ID, title, or statement keyword and reach the matching control directly. success -- searching 'AC-2' or 'account management' both surface AC-2; reachable without page reload from any screen.
- (capability) CAP-6 Deep-linking / sharing: intent -- user can share a URL to any meaningful state (family, control, expanded enhancement, baseline filter, search result) and have it load directly, no prior navigation. success -- every such state has a stable human-readable URL that round-trips correctly on cold load.
- (constraint) Static-site only: all data resolves at build time; no server/database/runtime API. Rules out any dynamic backend feature.
- (constraint) No accounts: public, free, no login.
- (constraint) Content fidelity: control statements/titles render verbatim from ingested OSCAL data, no paraphrasing anywhere in the pipeline.
- (constraint) Data provenance: every page states the source OSCAL Catalog version + crosswalk transcription date it renders.
- (constraint) Not an authoritative source: an unofficial/not-for-audit disclaimer renders on every page.
- (constraint) Single canonical ingestion pipeline: one local, human-run script is the only code path reading raw OSCAL/crosswalk source; its committed output is the only thing pages/components/CI may read.
- (constraint) Shareable UI state (baseline filter, expanded enhancement, search query) lives only in the URL, merged non-destructively -- never local-only component state.
- (constraint) Mobile-first, phone-readable layout required; no formal accessibility standard (e.g. WCAG 2.1 AA) targeted for v1.
- (constraint) Do not optimize for session length / engagement metrics -- a fast correct answer followed by leaving is success, not a retention failure.
- (constraint) Hosting: GitHub Pages via GitHub Actions artifact-based deploy; free/low-cost infra only.
- (constraint) Stack, routing/slug scheme, and every build-time invariant beyond the above are governed in full by the adopted ARCHITECTURE-SPINE.md companion -- not restated in the kernel.
- (decision) Non-goals: not a GRC/compliance-management platform (no tailoring/POA&M/800-53A assessment workflows); not official NIST publication or audit-ready record; not multi-framework in v1 (no CMMC/PCI-DSS, revisit only if requested repeatedly); not collaborative (no accounts/comments/annotations/saved views/export); not a native app (responsive web only); no withdrawn-control tracking or Rev4 comparison; no automated/scheduled re-ingestion in v1 (manual only); no scripted docx-parsing or OSCAL-native Mapping-model authoring for the crosswalk in v1 (hand-transcription only); no staging/multi-environment setup.
- (decision) Success signal: the builder (and anyone else who finds it) reaches for this instead of the PDF or NIST's own search whenever they need to look up a control, and still does a month after launch; people who find it organically come back more than once.
- (assumption) 'NIST 800-53 Browser' is a placeholder working title, not a confirmed product name.
- (assumption) Performance targets (~2s initial load, ~200ms navigation) are rough hobby-scope bounds, not measured/benchmarked.
- (assumption) Ingestion script's implementation language (Node.js) is a convention-following default, not a binding requirement -- local, one-off tool outside the deployed system.
- (question) What cadence should the maintainer use to manually re-run ingestion when NIST publishes catalog/crosswalk updates (quarterly check vs only on announced amendments)?
- (question) Exact disclaimer wording is undecided -- placement (global footer, every page) is fixed by the architecture spine, the copy itself is not.
- (question) Does Pagefind's default matching (may include fuzzy/typo tolerance) need tightening to match the 'plain substring is enough' v1 intent, and does it tokenize hyphenated control IDs (AC-2) correctly? Needs verification once search is built.
