- (event) Ran two parallel web-research subagents (practitioner workflow; tool landscape). Both converged independently on ODP (organization-defined parameter) authoring as the strongest unclaimed gap.
- (event) Research finding: FedRAMP Notice 0013 removes most FedRAMP-assigned ODP values for 2026 -- rationale 'a minimum bar also effectively establishes a ceiling'. CSPs must now choose and document their own ODP values, making ODP authoring a live and growing pain point rather than a speculative one.
- (event) Research finding: OSCAL is mandated-in-direction but effectively unused -- FedRAMP RFC-0024 states 100+ Rev5 authorizations processed in 2025 with zero OSCAL submissions. Implication: build OSCAL-exportable, never OSCAL-first.
- (event) Research finding: FedRAMP 20x deletes the narrative SSP (replaced by Certification Package Overview + Security Decision Record + 56/61 Key Security Indicators; mandatory Jan 1 2027). Implication: an SSP-narrative generator would target a deprecating artifact -- avoid as centerpiece.
- (event) Research finding: hiring-manager signal is 'defended judgment under ambiguity', not control mappings/policy templates/screenshots (explicitly named as resume padding). Catalog viewing is a solved, crowded space (EasyDynamics OSCAL Viewer, csf.tools, NIST's own planned portal).
- (decision) Cluster hypothesis verified structurally: no published ODP artifact is organized by parameter type (all per-control), but the underlying VALUES are standardized by parameter type and CNSSI 1253 explicitly permits addressing a parameter value once in org policy. Decision is batched; the artifact is denormalized. No practitioner-account confirmation found (Reddit/LinkedIn unreachable) -- carried as an assumption.
- (decision) Real vocabulary confirmed via data: the -1 (dash-one) controls are the correct term for the policy/procedure control cluster, not an invented 'policy-review cluster' term. 20 dash-one controls exist, 18 in Moderate baseline, each carrying exactly 9 ODPs including 2 frequency parameters (162 structurally identical questions in Moderate alone).
- (decision) Named architectural constraint from research: OSCAL has no parameter-reuse primitive -- profile set-parameter is strictly one-per-parameter, so a batched decision must fan out to N entries on export, and the 'decided once' rationale is lost in the OSCAL round-trip unless stored separately by the tool itself.
- (decision) Named product-level risk from research: FedRAMP Notice 0013 removed centralized ODP defaults specifically because defaults become unexamined ceilings ('almost no CSPs try to exceed the FedRAMP-assigned values'). The product's default-then-override design must actively surface which controls still hold an unreviewed default, not just offer overrides as an option nobody exercises.
- (decision) UJ-1 revised: replaced invented 'policy-review cluster' with verified dash-one controls (18 of 20 in Moderate, 9 ODPs each, 2 frequency params); made ceiling-effect risk visible in-journey via mandatory review-before-ready gate and rationale-on-override, not just an available toggle.
- (decision) Vision drafted: reconciled original four asks (status/notes/dashboard/export) as facets of one ODP-tailoring feature rather than separate shallow features -- status=parameter review state, notes=rationale, dashboard=baseline readiness %, export=real OSCAL profile with remarks. Non-goals sharpened: no multi-user/backend, no assessment-workflow authoring, Moderate baseline only for v1.
