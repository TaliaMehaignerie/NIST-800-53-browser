- (constraint) Inherited from PRD (NFR, no-backend): static-site generation, no server/database. Search runs client-side.
- (constraint) Inherited from PRD: web-only, responsive/phone-readable is a hard requirement; no native app in v1.
- (constraint) Inherited from PRD: every meaningful state (family, control, expanded enhancement, baseline filter, search result) must be deep-linkable via stable human-readable URL, loadable directly with no prior navigation.
- (constraint) Inherited from PRD: public, free, no login/accounts -- no auth/session system needed.
- (constraint) Inherited from PRD: data source is NIST's official OSCAL Catalog (Rev 5, all baselines) plus NIST's own OSCAL ISO 27001 crosswalk; content rendered verbatim, no editorializing; every page shows OSCAL release/version (data-provenance requirement).
- (constraint) Inherited from PRD: performance targets ~2s initial load, ~200ms between-page navigation (rough, unbenchmarked).
- (event) Working mode: Coaching path. Deliverable: spine only, no additional human-facing artifact requested.
- (decision) Paradigm/stack: Astro (static-first, islands architecture, typed Content Collections), chosen over Next.js static export, Eleventy, and Docusaurus. Reasoning: mostly-static per-control pages with a few interactive islands (search, baseline filter, enhancement expand) matches Astro's design center; typed Content Collections map cleanly onto Family/Control/Enhancement.
- (version) Astro 7.2.4 (current as of Aug 2026), requires Node 22+. Verified via astro.build blog and docs.astro.build/en/upgrade-astro.
- (question) Data source reality check (web-verified): usnistgov/oscal-content GitHub repo has the Rev5 Catalog + Low/Moderate/High baselines in JSON/XML/YAML, generated via CI/CD from source. Privacy baseline presence in that repo for Rev5 is unconfirmed (page only explicitly named low/moderate/high for Rev5). PRD commits to all four baselines -- needs verification before build.
- (question) ISO 27001 crosswalk reality check (web-verified): NIST publishes the SP800-53 Rev5 -> ISO/IEC 27001:2022 mapping as a .docx (sp800-53r5-to-iso-27001-mapping.docx via CSRC OLIR program), NOT as OSCAL-native structured mapping data. PRD's assumption of 'NIST's OSCAL crosswalk data' does not match reality -- affects ingestion pipeline design.
- (decision) Privacy baseline confirmed present in usnistgov/oscal-content (JSON): NIST_SP-800-53_rev5_PRIVACY-baseline_profile.json and resolved-profile_catalog.json exist alongside Low/Moderate/High. No scope change from PRD.
- (decision) ISO 27001 crosswalk ingestion: manual one-time transcription of the NIST .docx mapping table into a checked-in structured JSON file (canonical pipeline input), re-transcribed by hand on future NIST revisions. Chosen over scripted docx-parsing and OSCAL-native Mapping-model authoring for hobby-scope simplicity; user is open to revisiting scripted parsing later for the learning experience.
- (decision) URL/routing scheme approved: /families/{prefix}, /controls/{id}, enhancements as URL fragment on parent control (/controls/ac-2#ac-2-1), ?baseline= query param as a filter on list views (not a path segment), /search?q= for search results.
- (decision) Data pipeline: single build-time ingestion script reads all 4 resolved-baseline catalogs + master catalog + hand-transcribed crosswalk JSON once, merges into one canonical record per Control/Enhancement (baseline flags + ISO clauses attached), writes out as Astro Content Collection entries. Pages/components consume only the merged collection, never raw OSCAL directly.
- (convention) ID/slug convention: canonical display form is NIST's own uppercase (AC-2, AC-2(1)). URL slugs are lowercase-hyphenated: ac-2, ac-2-1 (parens dropped, replaced with hyphen). One conversion function, used everywhere -- no ad hoc casing.
- (version) Search: Pagefind (Rust-based, build-time static index, maintained astro-pagefind integration), verified current fit for Astro + no-backend constraint.
- (decision) Deployment/hosting: GitHub Pages. Build via GitHub Actions workflow triggered on push to main -- runs ingestion script, builds Astro static site, publishes to gh-pages. Chosen over Cloudflare Pages and Netlify/Vercel for simplicity (no third-party account beyond GitHub) given hobby scope.
- (direction) Automated/scheduled re-ingestion when NIST publishes catalog/crosswalk updates is deferred -- v1 ingestion is manually triggered locally (run script, review diff, commit, push). Ties to PRD Open Question 1.
